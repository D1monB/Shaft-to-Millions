# Контракт карти

Для автора моделей. Друг робить моделі в Blender і розставляє їх у Roblox Studio. Код їх **не створює**, а **знаходить**:
за **тегом** (Tags) і **атрибутами** (Attributes) у вікні Properties. Назва моделі й папка не важливі.

Як тільки на карті з'являється хоч один об'єкт із тегом, сіра заглушка для цього тегу в Studio більше не будується.
Джерело істини в коді: [src/shared/config/map-contract.ts](../src/shared/config/map-contract.ts).

## Теги

| Що це                | Тег         | Атрибут                    | Тип об'єкта                                   | Що робить код                                      |
| -------------------- | ----------- | -------------------------- | --------------------------------------------- | -------------------------------------------------- |
| Блок руди            | `OreNode`   | `OreId` (string)           | Part або Model                                | додає ClickDetector, підпис над блоком              |
| Магазин спорядження  | `Shop`      | немає                      | Part або Model                                | ProximityPrompt «Відкрити»                          |
| Зона скупки          | `SellZone`  | немає                      | Part (можна прозору, `CanCollide = false`)     | ProximityPrompt «Продати»                           |
| Табір шару           | `CampSpawn` | `LayerId` (number)         | Part або SpawnLocation (код вимикає `Enabled`) | дотик відкриває шар і ставить точку відродження     |
| Точка на поверхні (подорож) | `SurfaceSpawn` | немає                | Part (одна)                                    | сюди телепортує швидка подорож «Поверхня»           |
| Майданчик автобура   | `DrillSite` | `LayerId` (number)         | Part або Model                                | ProximityPrompt «Автобур»                           |
| Стійка скрині        | `Chest`     | `ChestId` (string)         | Part або Model                                | ProximityPrompt з назвою скрині                     |

## Дійсні значення атрибутів

| Атрибут     | Значення                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------- |
| `OreId`     | `copper` (шар 1) · `iron` (шар 2) · `silver` (шар 3) · `gold` (шар 4) · `titanium` (шар 5) · `iridium` (лише зона порталу на дні шару 5) |
| `LayerId`   | `1` Сірі Пласти, `2` Іржаві Порожнини, `3` Базальтова Глибина, `4` Титанові Ребра, `5` Ефірне Дно (назви 4–5 пропозиції) |
| `ChestId`   | `pet_chest`, `speed_chest`, `pickaxe_chest`                                                  |

Неправильний або відсутній атрибут не ламає гру: сервер пише одне попередження в Output і пропускає об'єкт.

## Рекомендована структура Workspace (для порядку, не для коду)

```
Workspace
  Surface/            поверхня: магазин, скупка, скрині (ділянки з лінією: теги буде додано окремо)
  Layers/
    Layer1/           один шар = одна модель (щоб потім вантажити шари частинами, StreamingEnabled)
      Ores/
      Camp/           SpawnLocation з тегом CampSpawn, LayerId = 1
      DrillSite/
    Layer2/ ...
```

## Правила для моделей

- Усе статичне **Anchored**. Жодних скриптів у моделях: уся логіка живе в коді.
- Блок руди 3–5 studs: гравець має легко влучити мишкою й пальцем на телефоні.
- Табори шарів 2 і 3 мають бути **нижче** за попередні: гравець відкриває шари по черзі, перестрибнути не можна,
  а між відкриттями має минути щонайменше 45 с (захист від телепорту).
- **Глибина для лідерборда** міряється від висоти `SurfaceSpawn` (метри = studs нижче неї × 0.5) і обмежується табором
  першого ще не відкритого шару (`CampSpawn` з його `LayerId`). Тому `CampSpawn` має бути для **кожного** шару
  2..LAYER_COUNT, а табори глибших шарів стоять нижче. Немає табору наступного шару: рекорд глибини не пишеться.
  Остання межа: 99 999 м. Глибина рахується лише над нерухомою геометрією (сервер кидає промінь вниз), тож усе, по
  чому ходять, має бути **Anchored**.
- Табір **не** є точкою появи нових гравців: код вимикає `SpawnLocation.Enabled`. Для старту на поверхні постав
  звичайний `SpawnLocation` без тегу.
- Розумна кількість полігонів (мобільні пристрої). Великі шари краще ділити на шматки.
- Анімації й звуки мають належати власнику гри (або групі), інакше в грі вони не програються.
- Лише власні моделі, текстури й звуки. Жодних чужих брендів і нічого з аніме, яке надихнуло ідею.
- Перед великою зміною зберігайте/публікуйте версію плейсу.

## Ділянки тайкуна (лінія машин, decisions 027)

Ділянки код знаходить за шляхом, а не за тегом, бо так їх побудував автор карти:

    Workspace/Map/Plots/PlotN        Model, атрибути Owner (number, 0 = вільна) і PlotIndex (number)
      Base                           Part, від нього рахується розташування фабрики
      Factory/Machines/<модель>      атрибут Stage (number) 1…12, порядок машин у лінії
      Factory/Conveyors/<частини>    атрибути ConveyorFlow (+1/-1), ConveyorSpeed; тег ConveyorAnim

| Атрибут | Де | Хто ставить | Що означає |
| --- | --- | --- | --- |
| `Owner` | ділянка | сервер | UserId власника, 0 = вільна |
| `Stage` | модель машини | автор карти | місце в лінії 1…12 |
| `Bought` | модель машини | сервер | ставиться на машину, коли вона з’являється після купівлі |
| `ConveyorOn` | частина конвеєра | сервер | `false` зупиняє анімацію стрічки (скрипт ConveyorAnimator автора карти) |

- Фабрику достатньо зібрати **лише на першій ділянці**. Сервер під час гри копіює її на кожну ділянку без `Factory`,
  з тим самим положенням відносно `Base`. Файл карти при цьому не змінюється.
- Якщо на якійсь ділянці фабрика вже є, сервер її не чіпає (можна зробити власну розстановку).
- Кнопку «Зайняти ділянку» сервер ставить на невидимій точці біля `Base.PlayerSpawn` (не на табличці: вона висока). На зайнятій ділянці: E «Скинути руду» на місці першої машини, F «Купити» на місці наступної.
- Зараз стрічки вмикаються всі разом, коли в лінії є що обробляти. Щоб вмикалися лише куплені частини, треба
  атрибут на кожному шматку конвеєра з номером машини, після якої він іде (поки не домовлено).

## Термінали сундуків (з 2026-11-25)

Сервер шукає їх за шляхом, теги ставити не треба:

    Map/Plots/<PlotN>/Terminals/Terminal_Pets         -> скриня улюбленців (pet_chest)
    Map/Plots/<PlotN>/Terminals/Terminal_PickaxeAura  -> скриня аури кирки (pickaxe_chest)
    Map/Plots/<PlotN>/Terminals/Terminal_CharAura     -> скриня аури швидкості (speed_chest)

- Усередині кожного термінала має бути Attachment `PromptPoint` (запасний варіант: `RollButton`). Кнопка «Подивитись»
  стає над ним на висоті грудей гравця (низ термінала + 3 стади), бо вгорі гравець її не бачить.
- Необов'язковий `ParticleEmitter` `RollBurst` (`Rate = 0`, атрибут `EmitCount`) спалахує в гравця, коли йому випав
  предмет. Рухомі частини анімує скрипт друга `MachineAnimator` (тег `MachineAnim`), а не наш код.
- Під час гри сервер додає в термінал невидиму частину `ChestStand` з тегом `Chest` і атрибутом `ChestId`.
  У файлі карти нічого не змінюється.
- Перейменування терміналів або папки `Terminals` вимкне сундуки: назви записані в `src/shared/config/map-contract.ts`
  (`CHEST_TERMINALS`).

## Ore spawn points (decision 034)

- `Workspace/Map/Mine/OreSpawns/Tier<N>/<any BasePart>`: one ore block per point, layer N's ore. The point's bottom
  is the block's bottom. Points may be invisible; their name does not matter.
- `Workspace/Map/Mine/TunnelEntrance/Portal` (BasePart): Tier5 points within 60 studs of it grow iridium.
- More points or a new tier folder need no code change (a new tier needs a layer and an ore in the config).

### Як код будує маршрут предметів по стрічці

Предмети на стрічці їдуть по маршруту, який сервер складає із шматків `Factory/Conveyors`. Для цього шматки мають
відповідати тим самим правилам, що й у скрипті `ConveyorAnimator`:

- кожен шматок стрічки має атрибут `ConveyorFlow` (+1 або -1); частини без нього в маршрут не входять;
- прямий шматок: рух уздовж локальної осі X, довжина дорівнює `Size.X`;
- кут (у назві є `Corner`): чверть кола радіусом 12 із центром у локальній точці (7.657, -7.657); при +1 рух
  від кінця з боку -X до кінця з боку +Z. Ці числа записані в `src/shared/features/line/tuning.ts`;
- кінці сусідніх шматків сходяться (пропуск не більше 8 студів).

Якщо змінити форму чи розмір кута, треба оновити числа в коді. Якщо маршрут зламаний, в Output з'явиться
попередження `[line] belt path ...`.
