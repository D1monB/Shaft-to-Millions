# Архітектура коду

Правила (feature slices, безпека, тести) описані в [CLAUDE.md](../CLAUDE.md). Тут описано, як вони реалізовані.

## Шари коду

```
src/shared/config/      ДАНІ: руди, кирки, сумки, взуття, шари, машини, рецепти, бури, скрині, предмети, теги карти
src/shared/lib/         загальні помічники: rate limiter, валідація, ремонт даних, форматування чисел, deepCopy
src/shared/features/    ЧИСТА ЛОГІКА кожної фічі (без Roblox API) + *.test.ts поруч
src/server/features/    сервіси: remote-обробники, перевірки, збереження, тіки
src/server/lib/         remote-обгортка (rate limit, pcall, лог зловживань), перевірки «гравець поруч», notify
src/client/features/    контролери: панелі, HUD, ефекти
src/client/lib/         UI-набір (HUD, панель, картки, прогрес-бар, сповіщення), ProximityPrompt-маршрутизатор
src/*/app/              лише запуск сервісів і контролерів у фіксованому порядку
```

## Фічі

| Фіча        | shared (логіка)                                    | server                                      | client                                   |
| ----------- | -------------------------------------------------- | ------------------------------------------- | ---------------------------------------- |

| mining      | рівні кирок, удари, кулдаун, відновлення, вихід руди | ClickDetector на блоках, усі перевірки     | підписи над блоками, прогрес, ефекти     |

| upgrades    | покупка наступного рівня, захист від подвійного кліку | магазин                                   | панель магазину                          |
| selling     | розрахунок продажу (той самий для показу і продажу) | скупка, множник від улюбленців             | панель продажу з розбивкою               |
| goals       | вибір однієї підказки                              | —                                           | рядок «🎯» у HUD                          |
| factory     | склад, черга з часом, офлайн, скасування, оцінка   | машини, склад, тік кожні 2 с                | панелі складу й машин із таймерами       |

| world       | —                                                  | сірі заглушки (лише Studio)                 | —                                        |
| hud         | —                                                  | —                                           | стовпчик статусу й кнопки                |

Фічі не імпортують одна одну напряму, коли це створило б зайву залежність. Наприклад, бонуси улюбленців
потрапляють у продаж через провайдер `setSellMultiplierProvider`: продаж не знає про екіпірування.

## Потік даних

```
клієнт ──(намір: RemoteEvent / ClickDetector / ProximityPrompt)──► сервер
                                                                     │ перевірка: аргументи, rate limit,
                                                                     │ «гравець поруч», стан, гроші
                                                                     ▼
                                                         змінює ProfileData (без yield = атомарно)
                                                                     │ markDirty(player)
                                                                     ▼
клієнт ◄──────────── StateUpdate (копія профілю без приватних полів) ─┘
   └─► HUD і відкрита панель перемальовуються з нових даних
```

Клієнт ніколи не надсилає чисел, які щось вирішують: лише id (рецепт, машина, предмет) і очікуваний рівень для
захисту від подвійного кліку. Таймери (фабрика, бур) рахуються від `Workspace.GetServerTimeNow()`, тому працюють
між серверами й офлайн.

Видобуток іде через `ClickDetector.MouseClick` на сервері: клієнт не може навіть «заявити» удар.
Кожен обробник проходить через `onClientRequest`: rate limit на гравця, `pcall`, лог зловживань лише з UserId.

## Збереження ([src/shared/features/profile](../src/shared/features/profile))

- ProfileStore із session locking: один живий сеанс на гравця. Профіль звільняється при виході та в BindToClose.
- Завантаження: міграції копії → заповнення нових полів значеннями за замовчуванням → ремонт (`sanitize.ts`) → перевірка форми.
  Пошкоджені значення виправляються й логуються, а дані з майбутньої версії не чіпаються (гравця кікає з поясненням).
- Нове поле з дефолтом не потребує міграції. Перейменування чи видалення поля, як і підняття стелі, потребує підняти `CURRENT_SCHEMA_VERSION` і додати міграцію з тестом.
- `purchaseIds` (квитанції Robux) ніколи не надсилаються клієнту.

## Тести

`npm test`: 207 тестів під Lune, без Studio. Покривають усю чисту логіку, зокрема поганий ввід (NaN, нескінченність,
від'ємні й дробові числа, спам, дублікати, зламані збереження) і властивості балансу (див. [economy.md](economy.md)).
Код, якому потрібен Roblox (сесії профілю), тестується через порти з фейками.
Один такий тест уже знайшов справжній баг: `math.min(x, NaN)` у Luau повертає `x`, і конвеєр бура при поганому
вводі віддав би весь буфер. Баг виправлено, тест лишився як регресійний.
