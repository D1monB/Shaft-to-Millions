# Інструкція для автора карти (одна сторінка)

Ти робиш карту й моделі, код їх сам знаходить. Тобі **не треба** писати скрипти. Достатньо поставити **теги** і
**атрибути** на потрібні об'єкти. Повна таблиця: [map-contract.md](map-contract.md).

## Як поставити тег і атрибут у Roblox Studio

1. Виділи об'єкт (Part, SpawnLocation або Model).
2. **Тег:** меню **View → Tag Editor**, у полі додай тег (наприклад `OreNode`) і постав галочку біля нього.
3. **Атрибут:** вікно **Properties**, унизу розділ **Attributes**, кнопка **+**. Вкажи ім'я, тип (`string` або
   `number`) і значення (наприклад `OreId` = `copper`).

Назва об'єкта і папка не важливі. Важливі тільки тег і атрибут.

## Що поставити на карті

| Що це | Тег | Атрибут | Скільки |
| --- | --- | --- | --- |
| Точка на поверхні, куди повертає швидка подорож | `SurfaceSpawn` | немає | **рівно 1** |
| Табір кожного шару | `CampSpawn` | `LayerId` (number): `1` … `5` | **по одному на кожен шар** |
| Блок руди | `OreNode` | `OreId` (string), значення нижче | багато |
| Магазин спорядження | `Shop` | немає | 1 |
| Зона, де продають руду | `SellZone` | немає | 1 |
| Майданчик автобура | `DrillSite` | `LayerId` (number) | по одному на шар |
| Стійка скрині | `Chest` | `ChestId` (string): `pet_chest`, `speed_chest`, `pickaxe_chest` | по одній |

Значення `OreId` (поверхи ями `Tier1…5`): шар 1 це `copper`, шар 2 `iron`, шар 3 `gold`, шар 4 `titanium`, шар 5 `obsidian` і рідкісний `etherium`.

## Шість правил, без яких щось не запрацює

1. **Усе, по чому ходять, має бути Anchored.** Лідерборд глибини рахується тільки над закріпленою підлогою.
2. **Табір шару 2 стоїть нижче за табір шару 1, а шару 3 нижче за шар 2.** Шари відкриваються по черзі.
3. **Табір має бути для кожного шару 1, 2 і 3.** Без табору наступного шару глибина гравця не записується.
4. **Блок руди 3–5 studs**, щоб влучити пальцем на телефоні.
5. **Табір не є точкою появи нових гравців.** Для старту на поверхні постав звичайний `SpawnLocation` **без тегу**.
6. **Лише свої або ліцензійні** моделі, текстури, звуки й анімації. Жодних чужих брендів. Анімації мають належати
   власнику гри, інакше вони не програються.

Модель-мобі й скрипти в моделях не додавай: уся логіка в коді.

## Як перевірити, що все зроблено правильно

1. Натисни **Play** (кнопка Play, не Run), пройдися картою.
2. Відкрий вікно **Output** (View → Output). Якщо тег чи атрибут неправильний, там буде **одне** жовте попередження з назвою
   об'єкта, і гра просто пропустить цей об'єкт, нічого не зламається.
3. Перевір очима: біля магазину й скринь має з'являтись підказка «натисни E», над рудою підпис, а
   дотик до табору відкриває шар.

Поки на карті немає жодного об'єкта з тегом, Studio сам будує сіру заглушку для цього тегу. Коли ти поставив свій, заглушка
зникає.

## Як розробник підключається до цієї карти

Для того, хто пише код (не для тебе, якщо ти робиш тільки модель):

1. Надішли розробникові файл місця (**File → Save to File**) або додай його до Team Create.
2. Розробник відкриває цей проєкт у Studio і натискає в плагіні Rojo **Connect** (порт `34872`).
3. Rojo чіпає тільки папки `TS` у `ReplicatedStorage`, `ServerScriptService`, `StarterPlayerScripts` і папку
   `rbxts_include`. Твоя карта не змінюється.
4. Один раз у **File → Experience Settings → Security** увімкни **Enable Studio Access to API Services**, інакше
   збереження прогресу в Studio не працює.

**Перед великою зміною** збережи або опублікуй версію місця (**File → Save to Roblox**), щоб було куди відкотитись.
