Задачі проєкту. Позначки: **[код]** робить розробник (з Claude), **[модель]** робить друг у Blender / Roblox Studio,
**[разом]** потребує рішення обох. Кожна задача закінчується Play-тестом у Studio: що перевірити, написано поруч.

## Етап 1. Перший шар: видобуток, сумка, продаж, прокачка, збереження

Порядок обрано так, щоб після кожного кроку було щось, що можна відчути в Play-тесті.

### 1.1 Видобуток і сумка (починаємо тут)

- [ ] **[разом] Контракт карти.** Узгодити, як друг позначає моделі, щоб код їх знаходив. Див. [map-contract.md](map-contract.md).
- [ ] **[модель] Тестовий шматок шару 1:** підлога, 3–5 блоків руди двох видів, точка спавну. Можна сірі кубики: красу додамо потім.
- [ ] **[код] Конфіг руд і шару 1** (`src/shared/config`): id, назва, ціна, міцність, час відновлення. Тест, що конфіг валідний.
- [ ] **[код] Чиста логіка видобутку:** скільки ударів потрібно (міцність руди проти сили кирки), кулдаун удару. Тести з поганим вводом.
- [ ] **[код] Чиста логіка сумки:** місткість, додати руду, заповнена сумка відмовляє. Тести.
- [ ] **[код] Сервер видобутку:** remote «вдарити блок», перевірка дистанції, кулдауну, rate limit; руда йде в сумку; блок зникає й відновлюється.
- [ ] **[код] Клієнт:** інструмент-кирка, клік по руді, лічильник сумки на екрані.
  - Play-тест: б'ю блок кілька разів, він зникає, лічильник сумки росте, повна сумка не бере більше.

### 1.2 Продаж і гроші

- [ ] **[модель] Точка продажу** на поверхні (будь-яка модель із зоною).
- [ ] **[код] Продаж:** у зоні продажу сервер атомарно перетворює сумку на гроші. UI грошей.
  - Play-тест: заходжу в зону, сумка порожніє, гроші ростуть на правильну суму.

### 1.3 Прокачка: кирка, сумка, кросівки

- [ ] **[код] Конфіг рівнів** кирки, сумки, кросівок (ціна, сила, місткість, швидкість).
- [ ] **[модель] Магазин** (стійка/NPC) і, за бажанням, моделі кирок.
- [ ] **[код] Покупка на сервері** (перевірка грошей, атомарне списання), кросівки міняють WalkSpeed із сервера.
- [ ] **[код] Підказка «що купити далі».**
  - Play-тест: купую кирку, блок ламається швидше; купую кросівки, бігаю швидше.

### 1.4 Збереження прогресу

- [ ] **[разом] Затвердити бібліотеку** (пропозиція: ProfileStore із session locking).
- [ ] **[код] Фіча `profile`:** порти, менеджер сесій, схема з версією, міграції, тести гонок (швидкий вихід/вхід).
- [ ] **[код] Підключити гроші, сумку й прокачку до профілю.**
  - Play-тест: заробив, вийшов, зайшов, усе на місці. (Studio: Game Settings → Security → Enable Studio Access to API Services.)

### 1.5 Ефекти й смерть

- [ ] **[код] Базові ефекти на клієнті:** частинки удару, «політ» руди в сумку, спливаюча сума продажу (object pool).
- [ ] **[код] Смерть (тимчасово):** відродження в таборі шару без втрат. Справжній штраф вирішимо після тестів.

## Відкриті питання для Етапу 1

- Назви й ціни перших руд (2–3 руди на шарі 1).

- Штраф за смерть (відкладено).
